1. Introduction

The Modbus Logger reads data from devices over the Modbus protocol (RTU via a serial RS-485/RS-232 port, or Modbus TCP) and logs it to CSV files and/or a MySQL database. The application can read any number of devices at the same time, displays their current values live, and automatically attempts to reconnect if the connection is lost.

2. Connecting to Devices

In the Connection panel on the left side of the window, select the connection type:

Connection TypeDescription
Serial (RS-485) Select the COM Port (the ⟳ button refreshes the list of available ports), the transfer rate (baud), the frame format (data bits/parity/stop bits, e.g. 8E1), and the timeout and number of retries for failed reads.
Modbus TCP Enter the IP address (or host name) and port of the device/gateway, along with the timeout and retries, same as for a serial connection.
Connection settings can only be changed while logging is not running. The Sample interval [s] (how often devices are polled), however, can be changed even while logging is running — the change takes effect immediately.

3. Managing Devices

The device list is shown in the middle Devices column. Each device has its own Slave ID (bus address) and its own register map (profile).

  • Add — opens a window for adding a new device.
  • Edit — edits the selected device (name, Slave ID, registers).
  • Remove — removes the selected device from the list (its register map remains on disk, since it may still be used by another device).

When a device is selected in the list, the panel on the right shows a table of its registers and current values, which are refreshed while logging is running.

4. Device Register Map (Profile)

In the Add Device/Edit Device window you edit the register map — the list of all values the application reads from that device. For each register you specify:

FieldMeaning
AddressModbus register address (e.g. 0x0100 or decimal).
Functioninput (fc 04), holding (fc 03), or constant — a constant value that is never read from the bus.
Name / UnitDisplay name and physical unit (e.g. °C, V, rpm).
Typeuint16, int16, uint32, int32, or float32.
ScaleThe raw value is multiplied by this number before it is displayed (e.g. to convert tenths to whole units).
Word orderThe order of the 16-bit words for 32-bit types — big or little.
ConstantUsed only with the constant function — a fixed value (e.g. a location tag) written into every logged row.
Important: the register map you edit in the device window belongs to that device only — changes do not affect other devices, even if they previously used the same template. To deliberately share the same register map between several devices, use the buttons below:
  • Load Profile — loads an existing saved register template into the editor (replacing the current contents).
  • Save as Profile ... — saves the current register map as a standalone, named template that can later be loaded by any device.
  • Delete Profile — deletes the selected saved template from disk.

5. Loading and Saving Configurations

The Load Profile and Save Profile buttons in the main toolbar (at the top of the window) act on the entire configuration: all devices together with the connection and logging settings, saved under a single name. This is useful if you have several different setups (e.g. different sites or test benches) and switch between them.

Do not confuse this with the register map of an individual device (section 4) — these are two separate concepts that both happen to use the word "profile" in the interface.

6. Starting and Stopping Logging

The START button in the top-left corner establishes the connection and starts the device polling cycle. While running, the button changes to STOP. Each device in the list shows its current read status (a colored dot: gray = not yet read, green = OK, red = error).

The Sample interval [s] determines how often devices are polled (and how often the interface display is refreshed). The Write interval (in the logging settings), on the other hand, determines how often the values read are actually written to CSV/MySQL — these two rates can differ.

7. Logging Settings (CSV / MySQL)

The Logging Settings button opens a window with the following settings:

CSV

  • Folder for CSV files (a relative path is resolved against the configuration folder).
  • Column separator (semicolon, comma, or tab) and decimal separator (comma or period).

MySQL

  • Connection details: host, port, database, user, password, table name.
  • The Fetch Columns button reads the existing columns of the selected table and offers them for mapping — for each column you choose the data source (measurement time, device name, status, a specific register, or a fixed constant).
The write interval cannot be edited while logging is running — settings in this window only take effect the next time logging is started.

8. Viewing Modbus Traffic (HEX)

The Modbus Traffic (HEX) button opens a window where you can watch the raw Modbus requests and responses live (in HEX format) while logging is running — useful for diagnosing communication problems.

9. Changing the Interface Language

In the top-right corner of the window, select a language from the drop-down list (SL/EN/DE/IT/ES). The application briefly restarts when the language is changed, so that the new language takes effect everywhere — in menus, messages, and the event log. The application remembers the selected language for the next launch.

10. Troubleshooting

ProblemPossible Cause / Solution
The COM port list is empty Check that the USB/RS-485 adapter is plugged in, then click ⟳.
"Unable to open port" The port may be in use by another program (e.g. another terminal, or an already running copy of this application).
"Unable to establish connection" (TCP) Check the IP address, port, and network connectivity (e.g. ping the device).
Device shows "error" / timeout Check the Slave ID, the bus wiring, RS-485 termination, and whether the register map matches the actual device.
Connection was lost while running The application detects this automatically, closes the connection, and attempts to re-establish it on the next cycle — the outage remains visible in the event log and in the CSV/MySQL record.
